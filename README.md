# DaB 傷害計算機

目前是 GitHub Pages 靜態裝備配置工具的開發版本。使用 TypeScript 前端、Git 管理的 JSON 資料及瀏覽器端計算，不設 API、資料庫、管理後台或登入。配裝與比較基準存在使用者自己的 `localStorage`。

## 本機查看

```sh
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run build
pnpm run preview
```

預覽網址為 `http://127.0.0.1:4173`。建置輸出放在 `dist/`。

## GitHub Pages

`.github/workflows/pages.yml` 已設定在 `main`／`master` 分支 Push 後建置並部署。第一次使用時，在 GitHub repository 的 **Settings → Pages → Build and deployment** 選擇 **GitHub Actions**。之後更新 `data/` 中的 JSON、將 `data/manifest.json` 日期改成實際更新日，Push 到預設分支即可發布新版。

## 目前範圍

裝備介面依遊戲位置排列：左冰與內裝在左側、角色示意在中央、冰武與武器在右上、右冰與飾品在右側。點選部位開啟該部位的搜尋選單與設定。位置與分組由 `data/equipment-layout.json` 控制。

已接入內裝強化／鍛造、內裝鑑定、電路板、芯片調校、武器強化／成長／鑑定／變換、巨型魔力石，以及原有裝備與魔法石。支援強/排褲開關、本機儲存及屬性、攻擊、最終傷害比較；比較基準保存輸入，更新 JSON 後會依新資料重新計算兩套配置。若比較基準缺少武器強化等傷害計算必要輸入，畫面會提示重新設定基準。

現階段已顯示公式已映射來源的屬性彙總與依計算機 B156:B163 轉換的攻擊區間、爆擊／極大機率及最終傷害。其他效果設定涵蓋使用者最多選擇三套、再依右冰裝備件數計算的套效、賦靈錄六個職業選擇、共鳴、襲擊套效、亞特瑪、稱號、場地、巔峰選項、寵物、公會噴泉、標誌、立繪／覺醒、百億套效及聖獸選項。飾品鑑定選項位於對應飾品部位，依裝備目錄的可鑑定狀態與鑑定效果條數顯示及計算；尚無法由試算表確認的裝備維持 `null`，更新資料後即可啟用。武器等級、武器強化／成長／鑑定／變換也會參與計算。傷害公式納入職業係數、職業爆傷被動、乘算爆傷、強者／排熱、適應力與 Boss 防禦。沒有可確認公式來源的額外條件 Buff／Debuff 不會被推定計入；若後續發現新的公式來源，仍需先映射後才能納入結果。芯片、電路板與強化／鍛造必須填完整一組輸入才會產生有效結果。

2026-09-28 的線上試算表範例可在預覽網址後加上 `?sample=live-sheet-2026-09-28` 載入，不會覆蓋本機原有配裝。頁面會按原始數值逐格比對，差異原因記錄於 `docs/live-sheet-comparison-2026-09-28.md`。

## 本次確認的規則

- 強/排褲魔攻強化使用 H21；Lv.13 Boss傷害／適應力使用 G7 對應數值；武器四個變換的強化來源一律為 B32。
- 鍛造致命傷害：0～2 為 0、3～8 為 3、9 以上為 6；超越技傷：0～5 為 0、6～11 為 3、12～17 為 6、18 以上為 10。取最高達成門檻，不累加不同階層。
- 正式與比較配置使用同一套計算函式。以上公式修正亦已套用到使用者提供的 Google Sheets 正式組與實驗組，並從重新匯出的試算表確認引用內容。

開發期回歸檢查：先執行 `pnpm run build`，再執行 `node --test tests/confirmed-corrections.test.mjs`。這不是 JSON 更新的額外發布門檻。

Calculation Engine 的公式與資料解析位於 `calculation/`。Google Sheets 線上現行公式是最終依據；未確認的來源對應不應自行補造。
