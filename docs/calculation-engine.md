# Calculation Engine 規格

公式以線上 Google Sheets 為準。Calculation Engine 使用集中管理的 TypeScript 模組和 JSON 資料，不在 UI 元件內執行公式。試算表於 2026-09-28 新增兩列以分離大師聖獸來源；下列列號均為變更後的現行位置。

## 計算順序

1. 由職業、裝備及其他選項解析出具名屬性來源。
2. 將兩套下衣的一般屬性各取一半後合併；「強者%」「排熱%」保留為獨立條件效果。
3. 彙總全角色屬性，再只對兩極化、適應力各自套用 60 上限。極大化不設 60 上限。
4. 按職業類型與武器參數計算攻擊力及上下界。
5. 依職業被動的遞減、乘算、非遞減類型計算致命一擊與極大化機率；上限為 100%。
6. 依 B163 傷害公式合併攻擊上下界、致命傷害、傷害倍率、強者／排熱調和、適應力及防禦因子。

### 爆擊與極大化

兩種屬性各自使用遞減、乘算、非遞減三種來源語意。遞減被動已進入 F1/G1，不在最終率重複加算。乘算因子依序逐項乘上 `1 + value/100`；非遞減來源在乘算後加入。黃色聖獸精靈石 B77 同時作用於爆擊和極大化；B103 只作用於爆擊，B105 只作用於極大化。最終率各自限制在 100%。

角色被動來源允許同一職業與屬性存在多筆，逐筆保留及運算；不可去重。B161/B162 目前由 JSON 職業效果彙總。試算表實驗組也使用 B160 的非遞減極大化輸入，不再沿用錯誤的爆擊輸入位置。

### B163 傷害公式

令 `p(x)=x/100`，最終傷害依試算表原式與運算順序：

```text
extremizedBase = (B157 + (B158 - B157) × B160) / 2 + B158 / 2
critFactor = B159 × (p(H1) + p(classCritDamagePassivePct) + T1) + (1 - B159)
conditionalFactor = 1 / (0.5 / (1 + p(N1)) + 0.5 / (1 + p(O1)))
adaptationFactor = 1 - p(Z1) + p(Q1) + p(W1)
defenseFactor = 1 / (1 - p(X1) × p(R1))

B163 = extremizedBase × critFactor
  × (1+p(I1)) × (1+p(J1)) × (1+p(K1)) × (1+p(L1))
  × (1+p(M1)) × (1+p(P1)) × conditionalFactor × S1
  × adaptationFactor × defenseFactor
```

T1 使用 `PRODUCT(1 + T3:T/100) - 150%`；角色原始乘算暴傷 50% 必須保留在乘積來源。例：10%、2%、5%、30%、50% 得到 79.7295%；再加角色基礎 150% 及 DaB 被動 30%，總爆傷為 259.7295%。

## 已知公式細節與驗算

- `C53` 使用物理職業係數；`D53` 固定使用魔法職業係數。`B153` 決定 B156:B158 攻擊路徑。
- 主表、實驗組的 B105 鞋子來源均引用各自模擬區 H39。強／排褲魔攻強化引用 H21；Lv.13 電路引用係數區 G7；武器變換強化固定取模擬區 B32。
- 內裝上衣乘算傷害來源為「強化等級 + 2%」：Lv.9／10／11 分別提供 ×1.11／×1.12／×1.13。
- 強者與排熱分別代表 Boss 血量高於 50% 與低於／等於 50% 的傷害加成，依 50%／50% 調和式處理。
- 試算表驗算案例：正式組 B157/B158 為 85970/186911，B159/B160 為 100%/100%，B163 快取值為 52,280,713.39；以完整來源值重算約 52,280,713.3905647。實驗組公式更正後 B163 為 52,647,563.32。
- 匯出檔會將部分 Google Sheets 公式包成 `__xludf.DUMMYFUNCTION`，因此不以 Excel 重算作為公式真值；公式核對以線上 Google Sheets 為準。

## 大師聖獸來源拆分

保留「聖獸潛力選單」。固定效果 E76、精靈石顏色效果 B77、潛力效果 C78/D78/H78/I78/Q78 分開記錄；大師聖獸裝備部位及迷鏡效果仍由 `master-beast-effects.json` 管理。模擬區與實驗組的聖獸精靈石顏色選單位於 S26，選項為黃或綠，預設黃。盔甲的鑑定與個別精靈石效果不套用；盔甲傷害來源只有既有套裝效果與迷鏡變換。

## 仍未泛化的效果

已明確映射的效果集中在 JSON 與 resolver 中。未來若有新的條件類型、屬性彙總順序或乘算階段，必須先在 Calculation Engine 增加有型別的計算規則並建立測試，再新增 JSON 資料；單加 JSON 不能自動表示新的數學行為。
